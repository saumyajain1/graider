# Frontend UX review

Reviewed on October 2, 2026. Requested fixes are grouped into eleven issues. The additional findings below are proposals and have not been implemented.

## Requested fixes

1. **Dashboard empty state.** Keep only “Create an assignment to get started.” Remove the extra instructions about pasting questions or uploading files.
2. **Profile actions.** Add account and sign-out icons. Sign-out uses a spinner while its request is pending.
3. **AI controls.** Use a shared purple button with a sparkle icon for question extraction/replacement, reference-answer generation, rubric generation, and individual/bulk grading. Provide an accessible “uses AI” label and tooltip.
4. **AI loading states.** Only the action that was started changes to its loading label and spinner. Generating one reference answer or rubric leaves the bulk button’s label unchanged. Other actions are disabled while generation runs. Refreshing that question preserves unsaved edits to other questions.
5. **Save and continue.** Workflow navigation validates drafts, saves changed editors and pending new items, waits for successful saves, and then changes pages. Invalid inputs or failed saves keep the user on the current page. Validate all drafts before starting writes; successful saves remain saved if a later request fails.
6. **Workflow navigation.** Add backward/forward arrows, Rubric → Submissions and Submissions → Review actions, and one page-level Back to submissions action on the review queue. Assignment overview also has Back to dashboard. Google’s sign-in button keeps its authentication wording.
7. **Question fields.** Rename Source label to Question number and Shared group to Shared question group. Add visible labels to the new-question form and explain how related questions and their context share a group. Clearing a saved number/group now sends an empty value instead of omitting the update.
8. **Favicon.** Replace the bright violet background with the website’s dark purple gradient, a white G, and a small grading checkmark.
9. **Mark allocations.** Require positive totals for scored questions. For unmarked assignments, AI reads the entire assignment and proposes allocations based on complexity; the prompt preserves explicit question marks and distributes any stated overall total. Teachers review the proposals in Questions. Fully marked structured documents retain deterministic extraction. Context remains unscored. Require rubric points to match each question total exactly before continuing or grading; reject invalid AI rubrics before replacing existing criteria. Legacy results without a valid denominator explain the missing total and require setting marks/regrading rather than displaying `2/0` or `0/0`.
10. **Inputs needed later.** Prevent empty reference answers, absent question marks, invalid criterion points, and mismatched rubric totals from reaching grading. Submissions shows the missing setup with links and disables AI grading until it is complete. A new submission needs a student name plus text or a file; Save and continue cannot discard an incomplete draft or a selected CSV. Preserve zero totals and zero per-question AI scores in CSV exports.
11. **Connected Google accounts.** Reuse the multicolor Google symbol in the profile menu and account page, with the provider name kept for accessibility.

## Optional-input audit

| Input                          | Decision and later behavior                                                                                                                                                           |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Question total marks           | Required and positive for scored questions; AI proposes a value when the source is unmarked. Context uses no total.                                                                   |
| Assignment total               | Derived by summing scored question totals. A total stated in the source guides AI allocation; there is no separate assignment-total field in the current data model.                  |
| Reference answer               | Required before rubric AI generation and grading. The reference-answer Continue action saves drafts and checks every answer.                                                          |
| Rubric criteria/points         | At least one positive criterion per question; allocations must sum exactly to the question total before grading. Individual edits may be saved while a rubric is being assembled.     |
| Student response text/file     | At least one is required. CSV rows need response text. Student identifier is optional and has a safe display/export fallback.                                                         |
| Question number/group          | Optional; a missing number falls back to the internal question key. A missing group does not prevent standalone grading. Existing values can be cleared.                              |
| Course/description/source file | Optional metadata; pasted assignment text can replace a file. AI question extraction requires nonempty assignment text. File/text priority needs the separate decision in finding 14. |
| Final score/confidence         | A blank final score deliberately uses the AI score. Missing confidence displays “n/a”; it does not become a zero score.                                                               |

## Additional findings for discussion — not implemented

Numbering continues from the requested issues. Priorities reflect likely impact on a teacher’s work.

12. **High — unsaved navigation and reloads.** Save and continue preserves drafts, but sidebar links, Back links, sign-out, and reloads can still leave a page without saving. Add a shared unsaved-changes guard with Save, Discard, and Stay choices, plus a reload warning. Decide whether drafts should also survive browser restarts. Evidence: editable page state is local; [AppShell](../frontend/src/components/layout/AppShell.tsx) links and [WorkflowBack](../frontend/src/components/WorkflowNavigation.tsx) navigate directly.
13. **High — finalization can miss unsaved review edits.** Finalize submission sends its own request without saving edited scores/feedback first. It also does not require clearing review flags. The API can finalize a submission without checking that every question has a valid reviewed result. Recommend Save and finalize, an atomic server-side completeness check, and an explicit decision about flagged items. Editing a finalized result should also clear its old completion timestamp. Evidence: [SubmissionReviewPage](../frontend/src/pages/SubmissionReviewPage.tsx) and `finalize_submission`/`save_grading_review` in [submission_workflow](../backend/apps/grading/services/submission_workflow.py).
14. **High — replacement file versus edited text is ambiguous.** Overview always submits the existing assignment text with a replacement file. The backend only substitutes extracted file text when that text field was omitted. Consequently, the file can change while questions still use the previous text. Recommend explicit “Use text from replacement file” and “Keep edited text” choices, followed by an extraction preview before replacement. Evidence: [AssignmentOverviewPage](../frontend/src/pages/AssignmentOverviewPage.tsx) and `AssignmentSerializer.update` in [serializers](../backend/apps/assignments/serializers.py).
15. **High — saved grades can become stale.** Changing question wording, reference answers, or rubrics does not mark existing grades as based on an older version. Changing totals can leave old result snapshots with different denominators. Recommend recording the grading-input version, showing an “Inputs changed” status, and letting the teacher deliberately regrade affected submissions. Preserve manual overrides and show what will change. Evidence: artifact update views versus result snapshots in [grading views](../backend/apps/grading/views.py) and [submission_workflow](../backend/apps/grading/services/submission_workflow.py).
16. **Medium — bulk AI replacement needs confirmation.** Generate all answers/rubrics replaces existing teacher content without a confirmation or a “fill missing only” option. Single generation also overwrites that item’s draft. Recommend defaulting bulk generation to missing items, with explicit confirmation for replacements. Scoped spinners are fixed in issue 4; overwrite policy remains undecided. Evidence: generation handlers in [reference answers](../frontend/src/pages/AssignmentReferenceAnswersPage.tsx), [rubrics](../frontend/src/pages/AssignmentRubricPage.tsx), and the backend generation views.
17. **Medium — review/export includes unfinished submissions.** Pending and failed submissions have Open review links leading to a page with no results. Export CSV includes all statuses, while its wording suggests completed marks. Recommend a clear queue status/filter and an export choice between all submissions and finalized results, with unfinished counts shown before download. Evidence: [AssignmentReviewPage](../frontend/src/pages/AssignmentReviewPage.tsx) and `build_assignment_results_csv_response` in [submission_io](../backend/apps/grading/services/submission_io.py).
18. **Medium — password recovery and account management are incomplete.** Password accounts have no forgot-password flow; Profile cannot edit the name/password or disconnect a provider. The Google collision message requires a remembered password. Recommend password reset first, then minimal profile controls and safe provider disconnection that preserves another sign-in method. Evidence: [LoginPage](../frontend/src/pages/LoginPage.tsx), [ProfilePage](../frontend/src/pages/ProfilePage.tsx), and [AuthNotice](../frontend/src/components/AuthNotice.tsx).
19. **Medium — mobile navigation takes most of the first screen.** The full seven-item navigation precedes the page header/content at narrow widths. The mobile preview showed the sidebar and profile header occupying nearly the entire initial screen. Recommend an expandable navigation drawer while keeping every workflow step discoverable, including disabled steps before opening an assignment. Evidence: responsive browser review and [AppShell](../frontend/src/components/layout/AppShell.tsx).
20. **Low — upload selectors retain old filenames.** Successful submission creation/import clears React’s file state but does not reset the native file input. Its visible filename can suggest a file is still queued. Recommend resetting the input after success while preserving it after failure. Evidence: form state resets and uncontrolled file inputs in [AssignmentSubmissionsPage](../frontend/src/pages/AssignmentSubmissionsPage.tsx).
21. **Low — save feedback and navigation focus are inconsistent.** Overview/submissions show success messages, while question/rubric/reference saves mainly disable controls. Page changes do not explicitly move focus to the new main heading or reset scroll position. Recommend consistent saved/error feedback and route focus/scroll management, tested with keyboard navigation. Evidence: page mutation handlers, [router](../frontend/src/app/router.tsx), and browser workflow checks.

22. **Medium — duplicate question numbers can confuse mapping and CSVs.** Only the internal question key is unique; two scored questions can have the same displayed number. Export column names use that display label, so duplicate numbers can produce duplicate CSV headers. Recommend warning about duplicate scored-question numbers and offering a renumber action, while allowing shared-context labels. Evidence: [QuestionPart constraints](../backend/apps/assignments/models.py) and CSV header construction in [submission_io](../backend/apps/grading/services/submission_io.py).
23. **Medium — readiness badges do not check actual completeness.** Assignment status considers a rubric ready when criteria exist, even if points do not match the question total or reference answers are absent. It can also say questions are ready when a legacy question has no marks. The new Submissions setup check prevents grading, but dashboard badges can still overstate readiness. Recommend deriving the badges from the same completeness rules, while distinguishing an incomplete draft from a grading-ready assignment. Evidence: `Assignment.workflow_status` in [models](../backend/apps/assignments/models.py).

Suggested follow-up order: 12–15 first because they affect preserved work and correctness; 16–19 and 22–23 next; 20–21 afterward. These decisions are separate from background grading (production-plan Step 9).

## Validation

- 131 backend tests passed against an isolated PostgreSQL 18 database, including ten new mark-allocation regressions.
- Repository lint/format checks, frontend production build, OpenAPI validation, and migration consistency checks passed. No schema migration or production database reset is required.
- Local browser checks covered multiple unsaved question edits, incomplete marks, preservation of a different answer/rubric draft during single-item AI generation, scoped spinners, overview saves, missing grading setup, new submission saves, and legacy results without totals. Desktop and narrow-screen layouts were reviewed with synthetic accounts/data.
- A live synthetic OpenAI check proposed `3 + 7 = 10` marks for an assignment with an overall total and no individual marks. The generated rubric for the three-mark question totaled exactly three. Output schemas were checked against [OpenAI’s Structured Outputs documentation](https://developers.openai.com/api/docs/guides/structured-outputs).
- Production accounts, assignments, uploads, and grades were not changed by these checks. Browser AI-loading checks used delayed local fixtures; the separate live AI check used synthetic prompts and a separate local database.
